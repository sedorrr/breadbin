Breadbin catalogs your C64 games from folders, network drives and the USB sticks of your Ultimate devices, shows what is stored where, fetches descriptions and pictures, and starts games directly on an Ultimate 64, a C64 Ultimate or a 1541 Ultimate II+.

Getting started

  1. Add a source: In the sidebar under “Sources” click ＋ and choose a folder with games – a mounted network drive works too. Scanning starts right away.
  2. Add a device (optional): Click ＋ next to “Ultimate devices”. “Search network” finds Ultimates on your local network.
  3. Set up descriptions (optional): Click ⚙ at the top and enter a free ScreenScraper account. Then click “Fetch all without description” in the “Descriptions” card.
  4. Play: Click a game in the list, pick the device on the right and press “Launch”.

Sources and scanning

  • Supported: PRG, P00, CRT, D64, D71, D81, G64, T64 and TAP, also inside ZIP archives. Disk directories and T64 contents are read and searchable.
  • ↻ rescans a source, “Scan all” scans them one after another. A second scan only reads what changed, so it is fast. Cancel it in the status bar at the bottom.
  • If a network drive is unreachable, Breadbin does not delete any entries.
  • Device sticks as a source: in the device's ⋯ menu → “Folder as source”. Files are read via FTP; the first scan of a full stick takes a long time.
  • Quick scan (per device source): files with the same name and size as in another source are taken over instead of downloaded – much faster. Such entries are marked; turn quick scan off in the ⋯ menu and the next scan checks them after all.
  • Identical files in several places appear once, with all their locations.

The list

  • Search by title, disk name, file names in the disk directory, genre or publisher. Spaces don't matter: “spacegun” finds “Space Gun”.
  • Filters: format, view (all, ★ favorites, recently launched), source, “with description”, “duplicates”. Click column headers to sort, click again to reverse.
  • “Group same games”: D64, cartridge, cracks and work-in-progress builds of one game share a row (×N = number of versions). Matching uses the ScreenScraper game number and the cleaned-up name – trainer tags like “+10HDG”, versions and dates are ignored.
  • 💾N next to a title: a game with N disks or sides.
  • The ● after a title means “description available”, ★ marks favorites.
  • “Random game” (or key Z) shows a random game from the current results – works together with filters and lists, e.g. “a random classic”.
  • “Export” saves the current list as a CSV file (e.g. for Excel).
  • Select several rows: Cmd-click (Windows/Linux: Ctrl-click), or Shift-click for a range. A summary panel appears on the right, see Corrections.

Details

The right panel shows pictures, description, facts, the disks of a multi-disk game, all versions, the disk directory in C64 style, all locations and the checksums. Click a picture to enlarge it. “Search the web” opens CSDb, GameBase64, Lemon64 and the C64-Wiki (and the ScreenScraper page) in your browser.

Ultimate devices

  • Supported: Ultimate 64 (Elite), C64 Ultimate and 1541 Ultimate II+ (untested). FTP and “Web Remote Control” must be enabled in the device menu.
  • Launch folder: Breadbin copies games there that aren't on the device yet. ⋯ → “Empty launch folder” only deletes files Breadbin put there – disks with saved games stay.
  • Saved games: if a game saves to a disk Breadbin copied over, the file in the launch folder changes. “Fetch saved game …” in the details of a disk game (next to “Launch”) fetches the saved games of that game, ⋯ → “Fetch saved games …” in the device row all changed disks – to a folder of your choice, as “Title (saved game 1a2b3c4d).d64”. If that folder is a source, they appear as versions of their own after the scan. If the disk was already on the device (nothing copied), the game saves straight into that file.
  • Copy to the device: mark several rows (Cmd- or Ctrl-click, Shift-click), then “Copy to device …”. The games end up with their own names in a folder on the stick – handy for favourites or one of your lists, which you then find in the Ultimate menu without a computer. Whatever is already on the device is not copied again.
  • Next to the device you see its firmware and, if needed, a ⚠ with hints on what does not work with it (for example firmware that is too old, or JiffyDOS as KERNAL – tapes do not load with it).
  • ⏻ powers the device on or off. Powering on works via Wake-on-WiFi if “Wake On Wi-Fi” is enabled on the device; a device that is off is woken up automatically before launching.
  • If the device has a network password, enter it under “Edit”; it is kept in the system keychain.

Launch and insert

  • “Launch” ends whatever is running on the C64 (it restarts the C64) and starts the game: PRG and cartridges directly; disks are inserted into drive A and loaded like LOAD"*",8,1 + RUN; T64/P00 are converted.
  • “Insert” only puts a disk into drive A, without restarting – for swapping disks in a running game.
  • Multi-disk games: “Disks” lists every disk/side in order – “Launch” on disk 1, “Insert” on each. Detected from the name (“Side 2”, “Disk 1”, “s1”) or from the folder (SUMMER1A, SUMMER1B, SUMMER1C).
  • Tapes (TAP) can't be started: the Ultimate has no remote command for that.
  • “Screenshot” (Ultimate 64 and C64 Ultimate): what the device is showing is saved as your own title screen or in-game picture (320 × 200, without border) – for example for the community data. The same button sits next to title screen and in-game picture in “Enter details yourself”. The Ultimate briefly sends its picture as a video stream; other receivers (such as a jukebox) lose it meanwhile. Network cable required: the Ultimate sends the video stream over Ethernet only; a device that is only on Wi-Fi delivers no picture. If no picture arrives despite the cable, a firewall may be blocking incoming UDP packets.
  • Automatic title picture (⚙ Settings, off by default): after “Launch” the app waits the set time (25 seconds by default) and takes a screenshot as your own title picture – only if the game has none yet. If you launch another game on the same device before that, the picture is taken for the new one. If it still shows a loader or an intro, replace it in the details.

Descriptions from ScreenScraper (optional)

  • Extra details and pictures from ScreenScraper are optional. You need a free account at screenscraper.fr; user name and password go into ⚙ (the password is kept in the keychain). “Test access” shows your daily quota.
  • Games are recognized by their checksums, even with cryptic file names. Optionally Breadbin also searches by name – such matches are marked “please check”. So are matches where ScreenScraper sends no checksum that fits the file (it then usually guessed from the file name).
  • “Fetch all without description” works through the whole collection, “Only for the current list” just the list. Breadbin looks up as many games at once as your account allows (at most 4, 1.2 seconds apart per thread) and slows down when ScreenScraper reports it is busy. Big collections still take hours. Cancel any time; clicking again continues.
  • The daily quota – especially for requests without a match – is limited. When it's used up, Breadbin stops; continue the next day.
  • The computer stays awake during scans and fetches (can be turned off in ⚙).

When a game was matched wrongly

  • “Wrong game” discards description and pictures; no later fetch brings them back.
  • “Choose another game” / “Find game manually”: search by name or game number and pick the right hit. Entries in your library come first – written yourself, from the community or already fetched from ScreenScraper; their details and pictures are taken over, so the PRG and D64 of a new game end up in one row. ScreenScraper hits follow. No fetch overwrites your choice.
  • “Separate” (on each version in the “n versions” list): an entry that ended up with a different game just because of its name – say a new game with the name of an old one – gets its own row again. “Group again” in its details undoes that.
  • “Delete details”: description and pictures are removed; the entry counts as not looked up.
  • Inside a group these corrections apply to the version shown only. If other versions share the same match, Breadbin asks “Only this version” or “All”; “Choose another game” has a checkbox for it.
  • Several at once: select rows, then “Match all to one game”, “Look up on ScreenScraper”, “Wrong game” or “Delete details”. Tip: for entries hidden inside a group, turn off “group same games” first.

Your own details

  • “Enter details yourself” (also for several marked rows): title, year, publisher, developer, genre, players, description and your own pictures (title screen, in-game shot, box). Your own details always come first; no fetch and no exchange file overwrites them. A picture saved as the wrong kind moves with “Use as in-game” or “Use as title screen”; if there is already one there, the two swap places.
  • Description in German and English: the dialog has one field per language; one is enough. The app shows the text in the interface language, or the other one with a note if it is missing. Submitting sends both languages, so every Breadbin user reads the text in their language. Genres come from a fixed list and are translated as well.
  • Written or edited: “Edit details” starts with what is already there. If that came from ScreenScraper, your entry counts as edited and is not shared – ScreenScraper does not allow passing on its data. “Write your own version” starts with an empty form; what you write there is yours and can be shared. The details pane shows which kind an entry is.
  • View “Written by you (shareable)” (selection next to the format): all games whose details go into the exchange file.

Clean up

  • Under Collection → “Clean up …”: how many contents are stored more than once and how much space the copies take (separately: several times within the same source), how many images were damaged or of unknown layout during the scan, and how many entries have no details yet.
  • “Show” sets up the list accordingly; the views “Without details” and “Damaged / unknown” are also in the view selector at the top. The duplicate files can be saved as CSV with all their locations.
  • Breadbin deletes nothing here – clean up in the Finder or Explorer, then scan again.

Lists, rating and notes

  • In the details under “For me”: your own rating (1–5 stars, click again to remove it), “Completed” and a notes field for codes and hints. It applies to all versions of the row and is saved at once. In the list, ✓ and the stars appear after the title.
  • Your lists (“Party games”, “With kids”): tick them in the details or create one with “New list …”; “Add to list” adds several marked rows at once. The lists appear in the view selector at the top; its last entry “Manage lists …” (also in the details) creates, renames or deletes lists – after asking, and the games stay in the library.
  • Lists and notes stay on your computer and are not shared.

Sharing with others (community)

Under Share in the sidebar you save the details you wrote yourself, with your own pictures, as an exchange file (ZIP); “Share with others” in the details pane takes you there. Anything taken from ScreenScraper is left out. The number next to “Share” shows how many games go in. You do not need a ScreenScraper account for this.

  • Reading a file: details match every file with the same content via its checksum, whatever it is called or wherever it is on your side. Details for files you do not have (yet) appear once you scan them.
  • Precedence: your own details, then the preferred source, then the other (⚙ → “Preferred source for details”). The default is the community: exchange files replace details from ScreenScraper (its pictures stay for missing picture types), and fetching from ScreenScraper leaves community details alone – unless you explicitly click “Look up on ScreenScraper” for a game. With ScreenScraper as the preferred source it is the other way round.
  • Taken-over details are marked in the details pane. If you edit them, they become your own (shareable).
  • Community database: “Update community data” downloads and reads the current state of the shared database from 8bitcavern.de (server selectable in ⚙). At start, Breadbin checks at most once a week whether there is a new state and reads it (can be switched off in ⚙). “Prepare contribution …” writes the details you wrote yourself into a folder in the database layout – for example the working copy of your fork of github.com/sedorrr/breadbin-db; from there you submit them as a pull request. Easier, without a GitHub account: “Submit contribution …” sends them to the contribution server on 8bitcavern.de, where they are reviewed and then added to the community data. Breadbin remembers what was already submitted and next time sends only what is new or changed (a checkbox in the dialog sends everything again). In ⚙ you choose the Breadbin server (default) or your own server with its own address, separately for community data and for contributions; contributions can also be switched off there (“Do not submit”). ScreenScraper is independent of this and optional. An exchange file or the repository downloaded as ZIP can also be opened with “Read exchange file …”.
  • Shared details are licensed under CC BY-SA 4.0.

Proposals to ScreenScraper

With an account set up: “Propose to ScreenScraper” (games with a ScreenScraper number) sends name, publisher, developer, release date, number of players, genres, description and your own pictures to the moderators. Players and genres are picked from ScreenScraper's lists; each genre is sent as its own proposal. The dialog shows what ScreenScraper has now; nothing is sent until you confirm. ScreenScraper adds games it does not know by itself once several members look them up.

Troubleshooting

  • Devices don't show up or always appear “off” (macOS): System Settings → Privacy & Security → Local Network → turn Breadbin on (or off and on again) and restart Breadbin.
  • “Test access” reports 403 or a login error: check your ScreenScraper user name and password – the user name, not the e-mail address; “Show password” shows what is in the field. The message tells whether your account or the developer credentials built into the program are rejected – please report the latter.
  • Fetching stops with “daily quota”: normal for big collections; continue the next day.
  • A game doesn't start: does the launch folder exist on the device (stick plugged in)? Are FTP and Web Remote Control enabled on the device?

Your data

Breadbin keeps a database and the downloaded pictures in the app's data folder (open it via “About Breadbin” → “Show data folder”). Your game files are only read, never changed; Breadbin only writes to a device's launch folder. Passwords are kept in the system keychain, never in the database.

Backup: “About Breadbin” → “Back up library …” saves the database (sources, devices, your own details, lists, notes, settings) and all pictures as one ZIP file. “Restore backup …” replaces the current library with it – for example on a new computer; the previous database stays in the data folder as spiele.vor-wiederherstellung.sqlite. Passwords are not included, they live in the keychain.

Breadbin only goes online for your devices, ScreenScraper (if set up) and 8bitcavern.de, which hosts the community data and a small file naming the newest Breadbin version. If a newer version exists, the status bar shows “Breadbin … is available” – a click opens the download page. Both can be switched off in ⚙. The server only counts these checks anonymously per day and version; no IP addresses, IDs or cookies are stored.
